## 1. 产品概述

### 1.1 一句话定位

为高校编程课配的一对一 AI 导师与学情诊断系统：把学生「卡住的那一刻」变成可见、可诊断、可干预的过程数据闭环。

### 1.2 背景与问题

- **挂科顽疾**：全球程序设计课挂科退课率 28–33%（Watson & Li 2014，161 门课元分析，部分课程达 50%）。
- **反馈稀缺**：程序设计大班师生比 1:100+，过程性反馈是奢侈品，卡点只能靠学生自己熬。
- **评估失真**：99.2% 中国大学生正在使用 AI（2025 大学生 AI 使用行为报告）；ITiCSE 2024 证实 ChatGPT 可从题目描述直接生成通过评测的完整代码且人人不同——传统作业评估与查重整体失效。
- **供给空白**：清华 AI 助教已验证方向（2023 年 8 门课 → 2025 年秋 402 门课、714 个教学班），但自研 GLM 路径无法复制；地方院校只能采购通用平台，超星/讯飞无代码沙箱、无过程数据能力，编程课恰好是它们最无力的课。

传统 OJ 只判对错，**丢弃了最有价值的层——过程数据**（多少次提交、错误如何演化、卡了多久）。SigmaMentor 的产品地基就是把这一层存下来（`submission_events` 表）并围绕它构建诊断与干预。

### 1.3 理论支点

| 理论 | 在产品中的落地 |
|---|---|
| Bloom 1984「2 Sigma Problem」：一对一辅导比传统课堂高 2σ | 产品命名与使命；用 AI 把一对一辅导规模化 |
| 维果茨基最近发展区（ZPD） | 反馈必须发生在卡住的那一刻，而非批改时 |
| Generation Effect（Slamecka & Graf 1982） | 导师 Agent 永不直接给答案，学生自己生成的答案记忆更牢 |
| 样例渐隐（worked example fading） | L3 同类样例：结构相同、数据不同的解法 |
| Khanmigo non-event 教训 | 只给访问权限不产生学习；干预必须由诊断主动触发，且长在课堂流程里 |
| Kestin 2025 哈佛 AI tutor RCT | 主动式 AI 导师有实证学习增益，支撑产品形态 |

### 1.4 愿景与阶段目标

- **愿景**：高校课程 AI 导师平台——每一门课的学生都有自己的导师。
- **楔子战略**：编程课切入（痛点最烈 · 验证最快 · 竞争最空）→ 高数 / 物理 / 写作 → 平台。
- **对齐官方赛题重点词**：学情诊断 + 作业辅导（重点交付）；个性化学习 · 教师备课 · 学习陪伴（由诊断数据自然生长，挂路线图）。

## 2. 用户与场景

### 2.1 角色

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 学生 | 编程课学习者，大班环境，普遍已用 AI 但用错（要答案） | 卡住时有人引导我自己解出来，而不是直接给代码 |
| 教师 | 大班程序设计课教师（含助教） | 一屏看清全班卡在哪，批改与查重不再失真，干预建议可执行 |
| 管理员（教务） | 学院/教务管理者（P2） | 数据不出校、可审计、可统计 |

### 2.2 核心用户故事

**学生侧**
- S1：我提交代码失败了，系统告诉我这次错在哪个知识点、和之前哪次错误同类，并给我一级提示而不是答案。
- S2：我连续卡了 40 分钟没人管时，导师主动出现，从定向提示逐级升级到同类样例。
- S3：我拍一张报错截图（手写伪代码也行），系统能读懂并诊断。（P1 多模态）

**教师侧**
- T1：打开看板，3 秒知道这个班本周哪个知识点卡的人最多、卡多久。
- T2：高危名单直接给出（连续卡点/多次放弃/轨迹异常），每个名字后面跟着证据链。
- T3：疑似 AI 代写的提交给我看三类过程证据，我来判断，系统不定罪。
- T4：一键生成下次课的针对性练习。（P1）

## 3. 产品原则（红线，优先级高于一切功能）

1. **永不直接给答案**。导师 Agent 四级引导（L1–L4）中任何一级都不产出完整可提交代码。
2. **绝不自动定罪**。代写检测只呈现过程证据辅助教师判断，不自动标记、不通知学生「作弊」。
3. **不替代教师最终教育评价**（官方赛题边界）。所有干预建议与证据均为辅助决策。
4. **数据不出校**。全私有化部署，教育数据合规硬约束。
5. **每个诊断结论可回溯**。诊断必须引用具体提交记录与轨迹证据，非黑箱打分。

### 4.2 P0 功能详述

#### F1 作业提交与沙箱判题（学生端）

- 流程：查看题目 → 在线编辑代码 → 提交 → 沙箱执行测试用例 → 即时结果（通过/失败+失败类型）→ 全过程事件写入 `submission_events`。
- 事件类型至少覆盖：编辑、编译错误、运行错误、部分通过、通过、放弃（超时无活动）。每次事件记录 `seq`、`eventType`、`detail`、`intervalMs`（与上次事件间隔毫秒）。
- **验收标准**：
  1. 一次提交产生 ≥1 条事件记录，时间间隔字段与真实操作误差 < 1s；
  2. 判题结果与标准答案用例集一致（用 10 道题目 × 每题 5 组用例回归）；
  3. 沙箱超时/死循环被正确终止，不影响下一次执行。

#### F2 卡点诊断反馈（学生端 + A1 诊断 Agent）

- 输入：该生本次及历史 `submission_events`。
- 输出：学生知识缺陷画像——卡点知识点、卡点时长、错误演化路径（编译错→运行错→部分通过）、关联历史同类错误。
- MVP 版为规则引擎（现 `diagnosis.ts` 已有基础：轨迹统计、错误聚类），复赛版叠加 LLM 增强解释。
- **验收标准**：
  1. 对预置的 20 条脱敏轨迹样本，诊断给出的「卡点知识点」与人工标注一致率 ≥ 80%；
  2. 每条诊断结论附 ≥1 条可点击回溯的提交证据；
  3. 诊断延迟（规则版）< 1s，（LLM 版）< 10s。

#### F3 四级苏格拉底辅导对话（学生端 + A2 导师 Agent）

- 学生可就当前卡点发起对话；导师按四级策略引导，升级条件：
  - L1 定向提示（默认）——「再检查一下循环的边界条件」
  - L2 策略提示——学生 L1 后仍卡（同型错误再犯或明确求助）——「对比 i < n 与 i <= n 在 n=5 时各循环几次」
  - L3 同类样例——L2 后仍卡——给出结构相同、数据不同的解法（样例渐隐）
  - L4 复盘提炼——解题成功后——「用自己的话说说这次错在哪类问题上」→ 回流诊断画像
- 会话写入 `guidance_sessions`；L4 复盘结论回流 `diagnoses`。
- **验收标准**：
  1. 注入「直接给我代码」类 10 组诱导话术，100% 不产出完整可提交代码（人工评审）；
  2. 升级策略按规则触发，不跳级、不降级（单测覆盖）；
  3. 对话上下文携带当前题目与最近诊断，答非所问率人工抽检 < 10%。

#### F6 班级学情看板（教师端 + A4 学情 Agent）

- 班级卡点热力图：知识点 × 人数 × 卡点时长三维度；数据来自 `analytics_snapshots`（现 `aggregateClassAnalytics` 已有聚合基础）。
- **验收标准**：
  1. 看板数据与底表 SQL 直查结果一致（对账测试）；
  2. 50 人班级一学周数据量下，看板加载 < 2s。

#### F7 高危名单（教师端）

- 规则：连续卡点 N 次 / 多次放弃 / 提交轨迹异常，输出名单 + 每人证据摘要。
- **验收标准**：预置 20 名模拟学生轨迹，高危名单召回率 ≥ 90%（人工标注对照），每名高危学生附可展开的证据链。

#### I1 LLM 调用层（pi-ai 适配器）

- 现状：`packages/llm` 已有 `SigmaLlmClient` 接口 + OpenAI 兼容 fetch 实现 + `resolveLlmConfig(LLM_MODE=cloud|local)`，pi-ai 适配器留 TODO。
- 目标：实现 pi-ai 适配器，统一走 pi-ai 调用；自定义 baseURL 指向 llama-server（本地），云端 API 一行配置切换。
- **验收标准**：
  1. `LLM_MODE=local` 指向本机 llama-server，`LLM_MODE=cloud` 指向云端 API，切换不改业务代码；
  2. 请求失败有重试与降级（诊断/导师任一 LLM 调用失败时回退规则版结果，服务不中断）。

#### I2 判题沙箱（容器隔离）

- 现状：`services/sandbox` 为 Bun.spawn 开发版，**红线：无隔离，不可暴露真实课堂**。
- 目标：容器隔离（每类题目语言运行时镜像，资源限额 CPU/内存/时间/网络禁用，进程数限制）。
- **验收标准**：
  1. 恶意样本集（fork 炸弹、内存耗尽、网络请求、文件系统越界、超长死循环）全部被拦截且宿主机无影响；
  2. 单次判题冷启动 < 3s（容器复用缓存后 < 1s）；
  3. 30 并发提交不串结果。

#### I3 过程数据采集（submission_events）

- 地基表，字段见 §6.2；采集不可阻塞提交流程（异步写入），事件不可篡改（只追加）。
- **验收标准**：提交主流程在事件写入失败时仍成功返回，事件最终一致（重试队列）。

#### I4 数据层切换 PostgreSQL + 引入 Redis（复赛前完成）

- 背景：MVP/复赛 Demo 用 SQLite 跑；初赛材料与 README 按生产形态 PostgreSQL 呈现，复赛前必须真实切换，保证 README 快速开始可复现。
- 范围：schema sqlite-core → pg-core（9 表）；JSON 列 text-json → `jsonb()`；client 换 postgres.js；migrator 换 drizzle-orm/postgres-js；`.env` 加 `DATABASE_URL`；本地 docker 起 postgres:18；Redis（会话缓存 + 事件采集队列）一并引入。
- **验收标准**：
  1. docker 起 postgres:18 + `DATABASE_URL` 配置后，`bun run db:migrate` 建表、三端起服务、提交→诊断→看板全链路冒烟通过；
  2. README 快速开始命令逐条可复现（与技术栈表口径一致）；
  3. oxlint/oxfmt 保持零 error。

### 4.3 P1 功能详述（决赛前，9.22）

#### F4 报错截图/手写伪代码识别（多模态）

- VLM 读报错截图与手写伪码照片，转为结构化错误/伪码文本进入诊断流。依赖 pi-ai 多模态能力。

#### F5 诊断驱动的主动干预

- 触发条件：连续 N 次同型错误 / 卡点超时未提交 → 导师 Agent 主动推送进入对话；干预记录写 `interventions`。
- 验收：模拟轨迹注入触发条件，推送到达率 100%，干预强度有上限（同一学生同一题目每日主动出现 ≤ 3 次）。

#### F8 代写过程证据链（教师端 + A3 评估 Agent）

- 三类信号：编辑轨迹（一次粘贴成型 vs 逐步演化）、版本序列（无失败记录的完美提交）、提交节奏（与能力画像不符的突变）。
- 输出：疑似度分级 + 证据链，仅教师可见。**红线：不自动定罪、不通知学生。**
- 验收：人工标注的 30 组（真人逐步 / AI 一次性生成）混合提交，证据页呈现三类信号完整，教师盲评认为「有帮助」≥ 80%。

#### F9 一键生成针对性练习

- 基于班级热力图 TOP 卡点知识点，生成下次课针对性练习（题目 + 用例），教师确认后发布。

#### 真实课堂试点（非功能项，但为决赛核心证据）

- 场景：本人主讲程序设计课程，每周实验课强制走平台（嵌入授课流程，非课外自愿——Khanmigo non-event 教训）。
- 采集：前后测对比、卡点时长、错误复发率、对照往届基线。
- 合规前置：学院/教务试点报备 → 学生知情同意书 → 数据脱敏。三者齐备前不开真实数据采集。

### 4.4 P2 路线图

- 课程包扩展：高数（公式推导验证）→ 物理（仿真）→ 写作（文献工具）。
- 开源数据集发布：脱敏编程课学习过程轨迹数据集（国内空白，CC BY 4.0）+ 提交轨迹分析框架 + 分级引导策略库。
- 高并发：vLLM 后端接入（GPU 集群），pi-ai 切换不变业务代码。
- 教务侧统计报表（管理员角色）。

## 6. 系统架构与数据模型（现状约束）

### 6.1 技术栈（已定，勿翻案）

bun monorepo ／ React19 + Tailwind4 + shadcn + TanStack（构建一律 Bun 原生 bundler，**不用 Vite**；Tailwind 走 CLI 或 PostCSS 接入）／ Elysia + Eden（api :3000）／ Drizzle：**MVP 用 bun:sqlite，生产环境 PostgreSQL 18**（切换见 I4；Redis 7 会话与事件队列随 PG 一并引入）／ pi-ai 调用层 ／ llama.cpp 主力推理（llama-server OpenAI 兼容协议；vLLM 预留）／ oxlint + oxfmt ／ Apache 2.0（代码）+ CC BY 4.0（数据集）。

> 分层策略（用户 2026-08-16 拍板）：开发与复赛 Demo 用 SQLite（零部署依赖、离线可跑），生产部署形态为 PostgreSQL（初赛材料与 README 按生产形态呈现）。复赛前完成 PG 切换（I4），保证 README 快速开始可复现。

### 6.2 核心数据模型（packages/db，9 表）

```
classes（班级）─┬─ students（学生）
               └─ assignments（作业）─ submissions（提交）─ submission_events（过程事件·地基表）
diagnoses（诊断画像）←─ guidance_sessions（辅导会话）
evidence_signals（代写证据）─ interventions（干预记录）
analytics_snapshots（学情快照/热力图）
```

关键约定（MVP/SQLite 期）：schema 用 drizzle sqlite-core；JSON 列用 `text("x", { mode: "json" })`（sqlite-core 无 json() 导出）；SQLite 路径用 `new URL("../xxx.sqlite", import.meta.url)` 锚定（相对解析以文件所在目录为基准）+ Windows 盘符修正 `.pathname.replace(/^\/([A-Za-z]:)/, "$1")`；迁移用 drizzle-kit generate + drizzle-orm/bun-sqlite/migrator（别用 drizzle-kit migrate——它要 node driver）。切 PG 后（I4）：pg-core、`jsonb()`、postgres.js、postgres-js migrator、docker 起 postgres:18、`.env` 配 `DATABASE_URL`。

### 6.3 Agent 闭环

诊断 → 干预 → 再诊断验证，过程数据持续回流。四 Agent 课程无关，编程课能力（沙箱/轨迹分析/分级提示引擎）在课程工具包层。
